# Feature 002 - Recomendación Personalizada de Cortes
**Fecha:** 20-09-2026 | **Estado:** ✅ Completada | **Sesión:** 1

## Objetivo
Endpoints asíncronos (`POST /api/recommend` → 202 + `job_id`, `GET /api/recommend/{job_id}` → polling) que recomiendan 3 cortes curados de un catálogo de 60, editan la foto del usuario con cada corte vía Replicate y entregan las imágenes en **base64 inline**. Consume el análisis de la Feature 001 **sin re-analizar** (ahorra 1 llamada Gemini por request).

## Arquitectura (Flujo)
```
POST /api/recommend (foto + analysis de /api/analyze)
   → validate_image (JPG/PNG, ≤10MB, PIL verify)
   → _parse_analysis (JSON, face_shape, gate confidence low → 400)
   → job_store.create_job() + schedule_job (asyncio.to_thread)
   → process_job (worker en hilo):
       HaircutService.generate_recommendations:
         1) Filtrar catálogo por face_shape + hair_type  (styles_data)
         2) La IA elige 3 estilos compatibles con razón   (AI.select_styles, sin skin_tone)
         3) Replicate edita SOLO el cabello por estilo (1 retry)
         4) base64 inline de cada imagen editada
GET /api/recommend/{job_id} → pending/processing/completed|failed + recommendations
```

## Decisiones Clave
| Decisión | Razón |
|----------|-------|
| **Asíncrono (202 + polling)** sobre síncrono | La generación de imágenes tarda 1-2 min; romper parcialmente el stateless fue un trade-off aceptado explícitamente |
| **Catálogo curado de 60 + la IA elige 3** | El catálogo fijo de 3 limitaba; el libre total es impredecible. La IA selecciona de un universo curado y da razones |
| **Sin re-análisis en 002** | `POST /api/recommend` recibe foto + `analysis` de `/api/analyze` → ahorra 1 llamada Gemini por request |
| **Imágenes en base64 inline** | Descartada la URL efímera de Replicate; el MVP no tiene storage |
| **Gate de cara con `confidence` del analysis** | Cero dependencias nuevas (descartados MediaPipe/OpenCV); `confidence: low` → 400 |
| **Fail-all con 1 retry por imagen** | Decisión explícita del usuario; un error deja el job en `failed` con el mensaje |
| **Selección IA sin `skin_tone`** | Evitar sesgo por tono de piel; el prompt lo prohíbe explícitamente |
| **Prompts de edición autocontenidos por estilo** | Se eliminó la concatenación `get_style_prompt()`; cada estilo describe su corte por completo |
| **Retry de 1 en `ReplicateClient.generate_image`** | Tolerar fallos transitorios sin bloquear demasiado el job |
| **Modelo de edición `google/nano-banana-pro`** | Líder conversacional para edición de imágenes según docs de Replicate (validado con Context7) |
| **3 ids legacy mantenidos** (`undercut`, `fade`, `textured-crop`) | No romper el pipeline viejo durante la transición |

## Errores y Soluciones
| Error | Causa | Solución |
|-------|-------|----------|
| `ImportError: cannot import name 'get_style_prompt'` | Fase D eliminó el shim pero `test_styles_data` aún lo importaba | Reescritura completa de tests en Fase E |
| Smoke de Fase C: job completed con lista vacía | El análisis mockeado no traía `recommended_styles` (diseño viejo) | El pipeline real de recomendación llegó en Fase D |
| `TypeError: 'tuple' object does not support the context manager protocol` | `_patch_pipeline()` devolvía una tupla, no un context manager | Convertir a `@contextmanager` que apila patches y cede `(mock_select, mock_gen)` |
| `TypeError: unsupported operand type(s) for *: '_patch' and '_patch'` | `patch() * patch()` ya no existe en Python 3.14 | Usar `contextlib.contextmanager` con `with` anidado |
| `TypeError: list indices must be integers` en test de candidatos | `call_args` se desempacó mal (`candidates` era el tuple de args completo) | `args, kwargs = call_args; candidates = args[0]` |
| `b'hello' != b'hello '` | base64 `aGVsbG8=` decodifica a `hello` sin espacio (assert mal escrito) | Corregir el valor esperado |
| Imagen base64 era base64 de la *URL* de Replicate | `generate_image` devolvía el string del output sin normalizar | `_to_bytes()`: descarga URL, decodifica data URI o usa bytes/listas |

## Validaciones Implementadas
| Validación | Tipo Error | Código |
|------------|------------|--------|
| Formato no JPG/PNG | Bad Request | 400 |
| Imagen > 10MB | Payload Too Large | 413 |
| Imagen corrupta (PIL verify) | Bad Request | 400 |
| `analysis` no es JSON válido | Bad Request | 400 |
| `analysis` sin `face_shape` | Bad Request | 400 |
| `confidence: low` (gate de cara) | Bad Request | 400 |
| Faltan `file` o `analysis` | Unprocessable Entity | 422 |
| Job inexistente | Not Found | 404 |
| Selección IA: ≠3 ids, duplicados o desconocidos | Job `failed` con error | 202 → GET `failed` |
| Sin estilos compatibles en catálogo | Job `failed` con error | 202 → GET `failed` |

```json
  ]

```

## Para Probar (Postman)
1. **Primero** `POST /api/analyze` (form-data: `file` = foto) → guardar el `analysis` del JSON.
2. `POST /api/recommend` (form-data): `file` = la misma foto, `analysis` = el JSON del paso 1.
3. Recibir `202` con `job_id`.
4. `GET /api/recommend/{job_id}` repetidamente hasta `status: completed`.
5. Decodificar cada `image_base64` para ver la foto editada.
> Requiere servidor corriendo, `.env` con `GEMINI_API_KEY` y `REPLICATE_API_TOKEN`.
